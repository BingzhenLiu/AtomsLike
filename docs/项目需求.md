# AtomsLike 项目需求

## 一句话定位

一个可运行的 Atoms Demo：用智能体生成应用代码并实时渲染为可视化网页，**并且管得住生成之后的事**——增量修改、版本快照、回溯与 diff。

**核心差异**：别人做「一次生成」，我们做「生成 → 修改 → 回溯」的闭环。

---

## 一、用户流程（主流程）

```
新建项目
  → 输入需求
  → Agent 输出计划（可见的步骤列表）
  → 流式生成代码（单文件 HTML）
  → 右侧 iframe 实时预览
  → 用户提出修改 → Agent 增量改
  → 每次改动落一个版本快照
  → 时间线回溯 / diff / 还原
  → 导出 HTML 或分享链接
```

## 二、功能需求

### P0（必须，缺一不可）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 需求输入 | 多行输入 + 一键生成 + 示例提示词 |
| F2 | Agent 生成 | 服务端代理调用 LLM，流式返回到前端 |
| F3 | 计划可见 | 生成前先输出步骤列表，提升"智能体感"与可解释性 |
| F4 | 代码提取 | 从模型输出中稳定提取 HTML 代码块，解析失败自动重试一次 |
| F5 | 实时预览 | iframe + srcDoc 渲染，sandbox 放行脚本 |
| F6 | 增量修改 | 基于当前代码做局部修改，非全量重生成 |
| F7 | 持久化 | 项目列表 + 版本快照存 IndexedDB，刷新不丢 |
| F8 | 版本回溯 | 时间线列出快照，点击还原 |
| F9 | 降级模式 | 无 key / 调用失败时切 mock，流程仍可完整演示 |
| F10 | 项目列表 | 首页展示历史项目，可新建 / 打开 / 删除 |

### P1（延展能力，时间允许做）

| 编号 | 功能 | 说明 |
|---|---|---|
| F11 | 版本 diff | 相邻版本并排/行级对比 |
| F12 | 导出 | 导出当前 HTML 文件 |
| F13 | 分享 | 生成只读分享链接（编码进 URL 即可，不做后端） |
| F14 | 错误自愈 | 生成代码报错时，把错误信息回喂模型自动修一次 |

### 不做（明确砍掉）

- 账号系统 / 登录注册（笔试里"注册"是举例，不是要求）
- 后端数据库、多用户、权限
- 多文件工程与依赖解析（单文件 HTML 已足够，多文件是稳定性黑洞）
- 移动端适配（桌面端为主）

---

## 三、非功能需求

| 项 | 要求 |
|---|---|
| 首屏 | 无 key 也能打开并走通流程（mock 保底） |
| 反馈 | 生成过程必须流式可见；任何等待都有状态提示 |
| 错误 | 可重试，错误信息对用户可读，不白屏 |
| 稳定 | 连续 5 次生成不因解析失败而中断 |
| 启动成本 | `npm i && npm run dev` 即可本地跑通 |

---

## 四、技术约束

- Next.js App Router + TypeScript + Tailwind v4
- LLM 调用走服务端 API route，key 只存在于环境变量
- 预览固定为**单文件 HTML**（内联 JS/CSS）
- 持久化用浏览器侧 IndexedDB，不上后端数据库
- 部署到 Vercel

---

## 五、验收标准（对应评估维度）

- **完成度**：主流程一遍跑通，无 key 也能演示，边界输入不崩
- **工程思维**：README + 说明文档写清取舍，主动交代砍了什么
- **用户体验**：三栏布局清晰，流式反馈，错误可重试
- **创新性**：版本快照 + 回溯 + diff 构成的"生成之后"闭环
- **可交付性**：文档齐备、链接可用、附演示录屏
