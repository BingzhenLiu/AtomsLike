## 三、核心差异化主张（决定创新分）

> 别人做「一次生成」，我做「**生成 → 修改 → 回溯**」的闭环。

主流程：
1. 输入需求 → Agent 输出**计划**（可看的步骤列表）
2. 流式生成多文件代码 → 右侧 iframe **实时预览**
3. 用户提出修改 → Agent **增量改**（不是重新生成全部）
4. 每一次改动存为一个**版本快照**
5. 底部时间线：任意版本**回溯 / 并排 diff / 一键还原**
6. 导出 / 分享

一举三得：**持久化**落在版本快照上（同时满足持久化 + 延展能力），**延展能力**就是版本树 + diff。

## 四、技术选型（省时间为第一原则）

- **框架**：Next.js（App Router）+ TypeScript —— 部署到 Vercel 最顺，API route 顺手解决 key 泄露
- **LLM**：走服务端 API route 代理，环境变量注入 key；支持自定义 baseURL
- **持久化**：IndexedDB（版本快照量大）或 localStorage（快）。**不要上后端数据库**
- **预览**：`iframe + srcDoc`。**限制生成单文件 HTML**（含内联 JS/CSS），避免多文件 import 报错——这是最大的稳定性来源
- **部署**：Vercel，推送即部署

### ⚠️ 必须做降级（mock）模式
评审打开链接时若 key 失效、额度耗尽、网络异常，页面直接白屏 = **完成度归零**。
做一个 `MOCK_MODE`：内置 2–3 个预置示例，无 key 也能完整演示全流程。**这是本次笔试最重要的一个工程判断。**

## 六、最容易踩的坑（按致命程度排序）

1. **部署留到最后** → 卡在环境变量/构建错误 → 交不出链接。**第 30 分钟就要有活链接。**
2. **没有 mock 降级** → 评审打不开 → 完成度 0 分。
3. **多文件预览翻车** → 限制单文件 HTML 输出，别贪。
4. **忘记设 public** → GitHub 私有 / 文档未公开 → 硬性不合格。
5. **AI 输出抖动**（多余解释、缺代码块）→ 结构化输出约束 + 解析失败自动重试一次。
6. **被"注册"二字带偏** → 原文写的是「如初始化 / 注册 / 核心主流程」，是举例。**不要花 2 小时做账号系统**，用"新建项目"替代。
7. **文档里的"完成程度"不敢写没做的** → 主动交代砍了什么、为什么，反而是工程思维的加分项。
