# 笔试需求（我方脱敏转述）

> ⚠️ **本文件不复制笔试原文，也不引用原文表述。** 笔试材料标注「仅限个人作答，请勿对外传播或共享」，
> 而本仓库按要求必须为 **public**，因此这里只保留我们自己要满足的**约束清单**，供开发自检使用。
> 原文及链接仅保存在本地，切勿提交进本仓库。

## 一、交付物

- 一个**可运行的网页应用**（Demo），具备"智能体驱动生成代码（应用）+ 将生成结果以可视化网页展示"的能力与交互体验。
- 一个**在线可测试链接**（自行部署）。
- 一个 **public 的 GitHub 源码链接**。
- 一份**说明文档**（强烈建议 → 按必做处理）。

## 二、硬性约束（自检表）

| # | 约束 | 我们通过什么满足 |
|---|---|---|
| 1 | 具备真实交互，而非纯静态展示 | 对话输入 → 生成 → 预览 → 修改，全链路可操作 |
| 2 | 具备数据持久化（技术方案不限） | 项目与版本快照落 IndexedDB |
| 3 | 覆盖基本使用流程（初始化 / 核心主流程） | 新建项目 → 生成 → 修改 → 保存 |
| 4 | 至少覆盖一个延展或衍生能力 | 版本快照 + 回溯 + diff |
| 5 | 提供可测试的在线访问链接 | Vercel 部署 |
| 6 | 实际可用，而非仅概念验证 | mock 模式保证任何环境下都能跑通 |
| 7 | 源码链接可访问 | GitHub public |
| 8 | 提交文档设为公开权限 | 提交前手动检查 |

## 三、时限

- 收到任务起 **48 小时**内提交。
- 建议投入一段完整的 **6–8 小时**专注开发。

## 四、评估维度（转述为自评口径）

| 维度 | 自评问题 |
|---|---|
| 完成度 | 功能是否完整、稳定，工程质量是否过关？ |
| 工程思维 | 任务拆解、技术选型、复杂度控制与取舍是否说清楚了？ |
| 用户体验 | 交互是否清晰、流程是否顺畅、是否真的"可用"？ |
| 创新性 | 有没有亮点设计、独特视角或可扩展潜力？ |
| 可交付性 | 文档是否清晰、能否跑起来、整体完成质量如何？ |

## 五、说明文档三块必备内容

1. 实现思路与关键取舍
2. 当前完成程度（哪些做了，哪些没做）
3. 若继续投入，如何扩展及优先级判断

## 六、可选加分

- 附 AI coding 工具的使用/充值账单。
